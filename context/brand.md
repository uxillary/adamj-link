## Experience Metaphor

adamj.link should not feel like browsing a traditional portfolio.

It should feel like entering a living digital operating system built around my work.

Visitors are exploring an active workspace rather than navigating a collection of pages.

The interface should evoke ideas such as:

- personal operating system
- mission control
- creative workstation
- engineering dashboard
- digital laboratory
- research terminal
- knowledge hub

The illusion should remain subtle.

The goal is inspiration, not roleplay.

## Living System Philosophy

The website should always feel alive.

Projects evolve.

Statistics update.

Activity changes.

Research grows.

Ideas appear.

The interface should communicate that work is continuously happening behind the scenes.

Nothing should feel abandoned or static.

Dynamic data should reinforce authenticity rather than exist purely for decoration.

## Data Visualization Philosophy

Data is a core part of the brand.

Whenever meaningful data exists, it should be visualised rather than hidden.

Preferred visualisations include:

- line graphs
- contribution graphs
- activity feeds
- timelines
- counters
- progress indicators
- trend charts
- completion bars
- system metrics
- repository statistics
- publication history

Visualisations should communicate progress, consistency and momentum.

Graphs should always represent real information whenever possible.

Avoid fake dashboards or meaningless statistics.

## Information Architecture

Content should be organised into self-contained modules rather than long scrolling sections.

Information should feel compartmentalised.

Examples include:

- system panels
- widgets
- cards
- terminal windows
- research logs
- activity feeds
- file explorers

Each module should communicate one clear purpose.

The overall interface should feel organised, technical and easy to scan.

- Activity
- System
- Research
- Status
- Timeline
- Logs
- Workspace
- Build
- Deploy
- Protocol
- Verification

## Interface Language

The interface should borrow terminology from engineering software and operating systems.

Examples include:

- Activity
- Timeline
- Research
- System
- Node
- Build
- Workspace
- Protocol
- Status
- Logs
- Repository

Terminology should support immersion without becoming confusing or overly technical.

## Authenticity

Every dynamic element should exist for a reason.

Statistics should represent real data.

Activity feeds should reflect genuine work.

Progress indicators should communicate meaningful progress.

The interface should avoid fake metrics or decorative numbers that exist only to impress.

Authenticity is more valuable than spectacle.

## Evolution

The website is never considered finished.

It should evolve continuously.

New systems, projects, experiments and ideas should naturally become part of the interface.

Returning visitors should occasionally discover something new.

The site should feel maintained rather than redesigned.

## Visual Motifs

Recurring design motifs include:

- subtle technical grids
- progress bars
- line graphs
- system status indicators
- timelines
- activity streams
- file explorers
- terminal references
- layered panels
- thin separators
- understated accent lighting

These motifs should reinforce the identity of a living technical workspace rather than dominate the interface.

# codex-rules.md — adamj.link

## Purpose

This document exists to preserve the identity, architecture, UX philosophy, and handcrafted feel of adamj.link when working with AI coding agents such as Codex.

The goal is to enhance the project without diluting its personality, performance, or intentional design direction.

Codex should behave like:
> a careful collaborator improving an intentionally crafted system

not:
> an autonomous rewrite engine.

---

## Core Priorities

Codex should prioritise:

- preserving existing systems
- maintaining handcrafted feel
- accessibility
- readability
- mobile usability
- lightweight interactions
- progressive enhancement
- performance
- incremental improvements
- maintainability
- visual cohesion
- uniqueness

The existing architecture and UX decisions are intentional unless explicitly stated otherwise.

---

## Development Philosophy

The project follows these principles:

- enhancement > rewrite
- readable > overabstracted
- static-first where possible
- modular but understandable
- lightweight over bloated
- intentional over trendy
- handcrafted over generated
- performance-aware by default
- subtle interactions over excessive animation

Avoid unnecessary complexity unless it meaningfully improves:

- UX
- maintainability
- accessibility
- scalability
- identity

---

## What Codex Should Avoid

Avoid:

- rewriting large working sections unnecessarily
- changing existing UX patterns without reason
- bloating files or architecture
- overengineering
- generic SaaS aesthetics
- bootstrap-like appearance
- dashboard syndrome
- excessive blur/glassmorphism
- childish animations
- generic Tailwind layouts
- “AI generated” feeling interfaces
- trend-chasing design decisions
- unnecessary dependencies
- duplicate systems
- giant PRs touching unrelated areas

The project should never feel:

- corporate
- templated
- generic
- mass-generated
- sterile
- startup-like
- fake
- overproduced

The project should feel:

- intentional
- technically informed
- polished
- subtle
- experimental
- internet-native
- modern
- alive

---

## Existing Codebase Rules

Codex should:

- preserve handcrafted details
- respect the current architecture
- extend existing systems before replacing them
- follow existing conventions and patterns
- avoid duplicate logic
- improve incrementally
- keep the project understandable to humans

Do not introduce unnecessary abstraction layers.

Prefer improving existing code over replacing entire systems.

---

## Changes Requiring Extra Caution

Exercise caution when modifying:

- APIs
- animations
- spacing systems
- typography hierarchy
- accessibility features
- performance-critical systems
- layout structure
- navigation flow
- existing interactions
- data pipelines
- theme systems
- handcrafted UI components

Large-scale rewrites should only happen when explicitly requested.

---

## Dependency Rules

Do not:

- install libraries without strong justification
- introduce frameworks unnecessarily
- replace lightweight systems with heavy abstractions
- convert working systems into React or SPA architecture without explicit instruction

Prefer:

- native browser APIs
- lightweight utilities
- simple maintainable solutions
- progressive enhancement

---

## UI & Interaction Direction

Generated UI should feel:

- subtle
- premium
- technical
- futuristic
- calm
- intentional
- internet-native
- visually satisfying
- understated
- polished

Interactions should:

- feel responsive
- avoid visual clutter
- remain lightweight
- maintain accessibility
- reward exploration subtly

Avoid excessive motion or gimmicks.

---

## Performance Expectations

Performance is a core feature of the project.

Codex should:

- minimise unnecessary JavaScript
- avoid layout thrashing
- avoid bloated bundles
- preserve responsiveness
- maintain fast page loads
- prefer efficient rendering patterns
- avoid unnecessary hydration

Performance should not be sacrificed for cosmetic features unless explicitly approved.

---

## Final Principle

adamj.link should feel like:
> a real creative developer’s evolving internet space

not:
> a generated portfolio template.

Every addition should reinforce:

- authenticity
- experimentation
- craftsmanship
- personality
- technical competence
- intentionality

The project should remain:
> the opposite of AI slop.
